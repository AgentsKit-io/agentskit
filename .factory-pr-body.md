## Review summary: #1819 `fix(memory): preserve vector data and harden persistence`

Reviewed against `main` for correctness, the persistence migration, data-loss risk, and test coverage of the vector path. The review and fix are in #1929 (ticket #1926).

### Findings
| # | Area | Finding | Status |
|---|------|---------|--------|
| 1 | `file-vector` (Vectra) migration | #1819 moves to stable Vectra IDs. Indexes written before it store each document under a **random Vectra ID**, with the public id in `metadata._id`. Re-storing that id added a new stable row and **left the legacy row in place**, so search returned stale copies next to the new one. | **Fixed**: commit 2e0b973c on #1929 |
| 2 | Redis vector | Vector bytes were corrupted by string decoding. #1819 keeps them as raw bytes (`redis-client.ts`, `redis-vector.ts`, `redis-chat.ts`). | OK in #1819, covered by `redis-client.test.ts` and `redis-chat-extra.test.ts` |
| 3 | File / localStorage KV fallback | Writes are now atomic (temp file plus rename for file storage; same-event-loop localStorage writes and expiry purges are kept). | OK in #1819, covered by `kv-store-localstorage-file.test.ts` and `kv-store-basic.test.ts` |
| 4 | SQLite KV eviction | Eviction runs inside a transaction when the opener supports one, so a crash cannot leave the store half-evicted. | OK in #1819, covered by `kv-store-sqlite.test.ts` and `sqlite.test.ts` |
| 5 | Mongo Atlas | Uses ordered ID upserts when the injected collection supports them. Canonical fields are replaced and unrelated host fields are kept. | OK in #1819, covered by `memory-batch-2.test.ts` |
| 6 | Lazy init | A failed lazy initialization is retried after best-effort cleanup of the internally owned resources that failed. | OK in #1819, covered by `turso-full.test.ts`, `sqlite.test.ts` and `redis-client.test.ts` |
| 7 | Other | Adapter-owned metadata fields are protected. Vector KV TTL recall is bounded to `k`, and rows from other collections are rejected (`kv-store-vector.test.ts`). Erasure failures are aggregated (`forget.test.ts`). | OK in #1819 |

### What was fixed and where
- **Commit 2e0b973c** (`fix(memory): replace legacy random-ID Vectra rows on id re-store`) on #1929. Upserting an id now also deletes legacy random-ID rows whose `metadata._id` matches. The delete runs inside the same `beginUpdate`/`endUpdate`, so if the batch fails the delete is rolled back with the rest of the update. The test is in `packages/memory/tests/file-vector.test.ts`, and the README notes the migration behaviour.
- **Changeset** `.changeset/quiet-memories-upsert.md` (`@agentskit/memory` patch) covers #1819 plus the fix.
- **CI**: the `Build all packages` step in `ci.yml` now runs on every build, not only when `run_all == 'true'`.
